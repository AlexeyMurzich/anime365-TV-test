# Навигация на Navigation 3, а не на Navigation Compose

В раунде 2 выбрали Navigation Compose с типизированными маршрутами. К началу
M0 стабильной стала Navigation 3 (`androidx.navigation3` 1.2.0) — новая
официальная навигация для Compose, в которой Google ведёт развитие. Берём её.

## Почему

- Стек экранов — обычный список ключей (`NavKey`), которым владеет наш код, а
  не скрытый внутри `NavController` граф.
- Каждая фича регистрирует свои экраны функцией
  `EntryProviderScope<NavKey>.xxxEntries()`; `:app` только перечисляет их.
  Это ложится на правило «фичи не видят друг друга» (ADR 0002).
- Раскладка «список + деталь» на планшете — стратегией сцен, а не руками.

## Следствия

- Отдельные стеки для каждого таба — свои: по одному `rememberNavBackStack` на
  таб в `Anime365App`. «Назад» на корне таба, кроме Главной, переключает на
  Главную; на корне Главной — закрывает приложение. Navigation 3 сама
  перехватывает «Назад», только когда в стеке есть куда возвращаться.
- Ключи навигации — публичный API фичи, поэтому `navigation3-runtime` и
  `kotlinx-serialization-core` подключаются к фиче как `api`.
- Переход из одной фичи в другую — лямбдой, которую передаёт `:app`
  (например, `onOpenSeries: (Int) -> Unit`), а не прямой ссылкой на ключ чужой
  фичи.
