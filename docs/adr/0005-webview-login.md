# Вход через WebView, а не через документированный /api/login

Токен доступа получается так: WebView открывает `/users/login` (где работает
и вход через ВКонтакте), после успешного входа приложение запрашивает
`GET /api/accessToken?app=...` в той же сессии. Формы email и пароля внутри
приложения нет.

## Почему не /api/login

Документированный метод принимает пароль **query-параметром**:
`GET /api/login?app=...&email=...&password=...`. Пароль в составе URL попадает
в логи веб-сервера, в логи любого прокси на пути и в историю запросов. При
нашей схеме приложение пароль не видит и не хранит вовсе, и бесплатно
получает вход через социальные сети.

## Следствия

- Токен хранится в DataStore, зашифрованный ключом из Android Keystore.
  Библиотека `androidx.security:security-crypto` не используется: годами в
  альфе и объявлена deprecated.
- Сам токен API требует передавать query-параметром в каждом защищённом
  запросе — тут выбора нет. HTTPS закрывает канал, но в логах сервера
  anime365 токен окажется. Это их схема, не наша.
- Токен не кладётся в секреты CI: репозиторий публичный (ADR 0007), а токен
  привязан к аккаунту с подпиской. CI гоняет тесты на записанных ответах
  сервера; тесты против живого API запускаются только локально и без токена
  пропускаются.
