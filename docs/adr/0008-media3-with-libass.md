# Плеер на Media3, ASS-субтитры рисует libass

Заменяет ADR 0003. Экран просмотра построен на Media3 с
`MediaSessionService`, а Отдельные субтитры рисует libass через расширение
`lib_ass_media` из [peerless2012/libass-android](https://github.com/peerless2012/libass-android)
(MIT, совместима с GPL-3.0).

## Почему пересмотрели ADR 0003

ADR 0003 считал потерю оформления ASS косметической. Проверка реального
фансаба (9volt, BD, 1-я серия Фрирен) показала обратное: 8004 строки
`Dialogue` из 8264 содержат теги оформления, стилей 14 — надписи на вывесках,
фуригана, караоке опенинга. Встроенный декодер Media3 выводит такие строки
обычным текстом, и они перекрывают диалоги внизу экрана.

## Рассмотренные варианты

- **Media3 без libass** — для субтитров непригодно, см. выше.
- **Media3 и фильтр, оставляющий только диалоговые стили** — чисто, но
  пропадают переводы надписей. Оставлен запасным вариантом.
- **libmpv** — полный ASS, но `MediaSessionService`, PiP и аудиофокус
  пришлось бы строить руками, как и описано в ADR 0003.

## Прототип (23.10.2026)

Samsung Galaxy Note 10, Android 12; Media3 1.11.1 и `ass-media` 0.5.1 (собрана под Media3 1.8 —
несовместимостей не нашлось), режим `OVERLAY_OPEN_GL`. На 1-й серии Фрирен:

- 9volt (BD, англ.): караоке опенинга с подсветкой слогов, надписи рядом с японским текстом на
  карте, которые едут вместе с панорамой (покадровый `\pos`, 288 строк в секунду).
- YakuSub (рус.): кириллица рисуется системным шрифтом вместо отсутствующих FrizQuadrataC и др.

Основной путь подтверждён, фильтр диалоговых стилей не нужен.

## Следствия

- В APK появляются нативные библиотеки, поэтому в GitHub Releases —
  отдельный APK под каждую архитектуру процессора; проверка обновлений
  выбирает нужный.
- Библиотека молодая (v0.5.1). Если её забросят — поддерживаем форк сами.
  Вся работа с ней — внутри `:core:player`, чтобы замена не расползалась по
  фичам.
- Шрифтов из стилей фансаба на устройстве обычно нет: libass подставит
  замену, надписи останутся на своих местах, но другим шрифтом.
