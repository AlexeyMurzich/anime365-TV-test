# Проект нарезан на модули по фичам, границы задаются правилами зависимостей

Код разделён на `:app`, набор `:core:*` (model, common, network, database,
datastore, data, designsystem, ui, player) и набор `:feature:*` (catalog,
series, player, library, account, upload). Цель — не скорость сборки, а
принудительные границы: модуль не может использовать то, на что не объявил
зависимость.

## Экраны по фичам

| Фича | Экраны (docs/screens.md) |
|---|---|
| `:feature:catalog` | Главная, Каталог |
| `:feature:series` | Аниме, Выбор Перевода |
| `:feature:player` | Плеер |
| `:feature:library` | Список (Библиотека и Скачанное) |
| `:feature:account` | Вход, Нужна Подписка, Профиль, Настройки |
| `:feature:upload` | Публикация, Мои публикации |

## Правила зависимостей

- `:feature:*` **не видят друг друга**. Переход между фичами идёт только через
  навигационный граф, который склеивает `:app` (ADR 0009).
- `:feature:*` зависят только от `:core:*`, причём не от `:core:network` и
  `:core:database` напрямую: данные фичи получают из репозиториев `:core:data` —
  единственного места, где встречаются сеть и база (ADR 0004).
- `:core:model` не зависит ни от чего, включая Android SDK.
- `:app` не содержит бизнес-логики: Application, Activity, граф навигации,
  граф Hilt.

Правила держатся не на договорённости, а на самих объявлениях зависимостей:
нарушение не компилируется.

## Следствия

- Вся обвязка (Compose, Hilt, KSP, Kotlin-опции, тестовый стек) живёт в
  convention plugins в `build-logic`. Без этого один и тот же блок настроек
  пришлось бы держать в четырнадцати build-файлах, и мультимодульность
  превратилась бы в налог вместо границы.
- Общий код, которому не нашлось места в существующем `:core:*`, не
  складывается в `:core:common` по умолчанию — `common` только для Result,
  диспетчеров и типов ошибок.
- Модуль без кода — заглушка без плагинов: Android-плагин, Hilt и прочее
  подключаются вместе с первым кодом. Иначе dependency-analysis справедливо
  требует превратить пустой Android-модуль в JVM-модуль и убрать
  неиспользуемые зависимости.
- Hilt фича подключает сама (`anime365.hilt`) вместе с первой ViewModel, а не
  через convention фичи.
- `:core:testing` — фейки репозиториев и правило диспетчера для unit-тестов фич; подключается
  только как `testImplementation`.

## Дизайн-система

- `:core:designsystem` не знает доменных моделей: цвета, типографика, формы и
  компоненты без логики (кнопки, чипы, бейджи, поле поиска).
- Компоненты, которые нужны нескольким фичам и при этом знают про Аниме,
  Эпизод или Перевод (выбор Перевода, сетка Эпизодов), живут в `:core:ui`.
  Иначе их пришлось бы дублировать: экран Аниме и Плеер — разные фичи и друг
  друга не видят.
- Источник цветов, типографики, отступов и радиусов — `tokens.json` из
  дизайн-системы Kadr, лежащий в репозитории. Kotlin-код темы генерируется
  из него задачей в `build-logic`; руками его не правят.
